The Rule

A player who is traded during the season becomes ineligible to keep for the manager who receives them. Only the manager who originally drafted the player may keep them — unless the player gets cut and re-added by someone (including the original drafter), in which case the player becomes keeper-eligible again for whoever picks them up.

How This Works

This tool reads your league's public Sleeper transaction history and, for every player currently rostered, walks backward through every trade, waiver claim and free-agent pickup to find the most recent way that player joined their current roster:

  • No transaction on record for this roster → the manager drafted them. Eligible.
  • Most recent add was a trade → Not eligible. Only the original drafter could have kept them.
  • Most recent add was a waiver claim or free agent pickup → the player was cut and re-added. Eligible for whoever picked them up.

Only transactions with status complete count — vetoed and failed moves are ignored.

Sleeper starts a brand-new league_id each season, resetting the transaction log to empty even though rosters carry over. Since keeper eligibility is decided by what happened last season, this tool reads current rosters from this year's league but reads trade/waiver history from last season's league_id (matched to this year's managers by their Sleeper account, not by roster number, since those can shuffle between seasons).

A Note On Edge Cases

Weird transaction sequences (e.g. a manager re-acquiring a player they themselves traded away) get flagged gold rather than guessed at. This is a shared, automated tool with no manual override — if something looks wrong, hash it out in the group chat.

Data Source

Everything is computed live, in your browser, from Sleeper's public API. No login, no accounts, no backend, no data stored anywhere except your browser's local session cache (to avoid re-downloading the ~10MB player database).
